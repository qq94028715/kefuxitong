# kefuxitong v0.8 · 知识点掌握度引擎改造方案

> 版本：v0.8 草案 · 2026-08-13 · 状态：**M1~M4 已实施完成**（后端集成测试通过、前端构建通过；M5 待真实数据调优）
> 本文档是「重新定位后」的改造依据，审阅确认后按里程碑 M1~M5 实施。

## 1. 背景与定位

### 1.1 系统目的（重新定义后）

**用 AI 扮演客户做情境对话训练，AI 初评、主管复审，沉淀每个客服的知识点掌握度图谱，系统自适应出题专补薄弱点，直至达标。**

类比：像 AI 给学生做题并考察掌握程度——衡量对象是「人」（这个客服对每个知识点掌握多少、薄弱点在哪），而不是「题」（这道题过没过）。

### 1.2 现状盘点（v0.7 已有基建）

| 能力 | 现状 | 说明 |
|---|---|---|
| 题库 | ✅ Question | 由上传聊天记录转题 + AI 衍生题 |
| 批次训练 | ✅ TrainingBatch / BatchQuestion | 固定 20 题一批 |
| 错题本 | ✅ MistakeLog | 判错题间隔重练直到通过 |
| 评分 | ✅ Score | AI 四维加权评分（需求确认/产品专业/报价/风控） |
| 判定 | ✅ BatchQuestion.review_status | pending / approved / rejected（主管复审） |
| **知识点掌握度** | ❌ **缺失** | **本次改造核心** |

### 1.3 本次目标

在现有「题」维度之上新增「**知识点（Skill）**」维度，形成闭环：

```
知识点掌握度图谱 → 自适应出题（挑薄弱点/递进难度） → 客服作答（情境对话）
      ↑                                                       ↓
   写回图谱  ←——— 判定掌握（AI 初评 → 主管复审 → 更新掌握度）
```

### 3.4 迁移方案（复用现有机制，不删库）

- 新表 `skill` / `skill_mastery`：`Base.metadata.create_all` 自动建（main.py `init_db` 已有该调用，**零改动**）。
- `question` 补列：扩展 `_migrate_legacy_columns()`，仿照 `batch_question_id` 的 ALTER 模式补 3 列，迁移失败仅告警不阻塞启动。
- 默认示例：`init_db` 为两个默认分类写入示例知识点（对应 DEFAULT_KNOWLEDGE 的 required_questions，如「尺寸确认」「材质工艺确认」「报价能力」）。

## 4. 掌握度算法（决策 #11）

### 4.1 公式：EMA 指数移动平均

```
mastery_new = (1 - α) × mastery_old + α × judgment

judgment：通过 = 100；主管驳回 = 0，且 α 翻倍（α_reject = 2α）
```

- α 默认 **0.3**（config 可调 `MASTERY_ALPHA`），体现「新判定权重更高」。
- 驳回翻倍：一次主管驳回 ≈ 两次通过的分量，防止「刷题刷到达标」。

### 4.2 状态阈值（决策 #2，三档）

| status | 区间 | 含义 |
|---|---|---|
| weak 薄弱 | mastery < 50 | 自适应出题重点照顾 |
| pass 及格 | 50 ≤ mastery < 80 | 正常巩固，可升难度 |
| master 达标 | mastery ≥ 80 | 不再优先出题，错题本除外 |

### 4.3 演算示例（α=0.3）

| 操作 | 结果 | 状态 |
|---|---|---|
| 初始 | 0 | weak |
| 通过 | 30 | weak |
| 通过 | 51 | pass |
| 通过 | 66 | pass |
| 通过 | 76 | pass |
| 通过 | 83 | **master 达标** |
| 主管驳回（α=0.6） | 33 | 回落 weak |

## 5. 自适应出题算法（决策 #8）

### 5.1 选题优先级（20 题一批，按序填充）

1. **错题重练**（最高优先）：MistakeLog 中未 resolved 的题（复用现有错题本）
2. **薄弱点**：weak 状态知识点下、未通过或最近答错的题
3. **难度升级**：pass 状态知识点下，比上次作答更高难度的题
4. **巩固/新题**：品类内未练过的题（含 AI 衍生题）

### 5.2 难度递进（决策 #9）

| 当前掌握度 | 出题难度 |
|---|---|
| < 50（weak） | easy |
| 50~79（pass） | medium |
| ≥ 80（master） | hard |

答对 → 该题难度升一档；主管驳回 → 降一档。

### 5.3 批内配比（默认，可配置）

错题 20% + 薄弱点 50% + 巩固 20% + 新题 10%。题不足时按比例顺延。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 旧题无 skill_id | 迁移置 NULL 归「未归类」，出题跳过；提示管理员可手动归类 |
| 知识点提炼质量不稳 | 管理员可编辑兜底；skill 带 version，重新提炼不覆盖手动修改（同 knowledge 机制） |
| AI 初评波动 | 主管复审兜底；驳回权重翻倍 |
| 刷题虚高 | EMA + 驳回翻倍 + 连续判定才有意义 |
| 样本量小导致掌握度剧烈波动 | α 可配置调低（如 0.15） |

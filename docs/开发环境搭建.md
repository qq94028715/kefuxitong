# 开发环境搭建（新电脑从零开始）

> 适用场景：在一台全新的 Windows 电脑上，从 GitHub 拉取代码并跑通 kefuxitong 客服系统。
> 已对照 v0.7 仓库结构校验（commit `a9c886a`）。

## 一、装工具（一次性）

| 工具 | 版本 | 验证命令 |
|------|------|----------|
| Git | 最新 | `git --version` |
| Python | 3.13.x | `python --version` |
| Node.js | 22.x（LTS） | `node -v` |

官网下载安装即可，安装 Git / Python 时记得勾选「Add to PATH」。

## 二、克隆代码

```bash
git clone https://github.com/qq94028715/kefuxitong.git
cd kefuxitong
```

代码全部在 GitHub（origin/main），`git clone` 即可拿到全部源码与 git 历史。

## 三、后端环境

依赖已锁定在仓库（见 `backend/requirements.txt` 与 `backend/requirements.lock.txt`），新电脑装到的版本与开发机一致。

```bash
cd backend
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
cd ..
```

> 国内镜像加速（下载慢时）：
> ```bash
> .venv\Scripts\pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
> ```

## 四、前端环境

```bash
cd frontend
npm install
cd ..
```

> 国内镜像：`npm config set registry https://registry.npmmirror.com`

## 五、拷贝 3 个私有数据（旧电脑 → 新电脑）

以下 3 样被 `.gitignore` 排除，不会进 Git，必须手动迁移：

| 要拷的文件 | 位置 | 内容 | 不拷的后果 |
|-----------|------|------|------------|
| `kefuxitong.db` | `backend/data/` | 全部用户 / 语料 / 知识 / 会话 / 评分 | 空库，从零开始 |
| `uploads/` 目录 | 项目根 | 上传的原始培训材料 / 聊天记录 | 材料列表空 |
| `.env` | `backend/` | `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL` 等 | 无 LLM，走规则模式 |

拷完 `backend/data/kefuxitong.db` 后，**首次启动会自动完成 v0.7 迁移**（补列 + 建表），旧数据直接可用，无需手动处理。

> `.env` 怎么来：把 `backend/.env.example` 复制为 `backend/.env`，再填真实值。`.env` 不入库。

## 六、启动（首次）

```bat
scripts\start.bat
```

会同时拉起两个窗口：

- 后端 API：http://localhost:8000 （接口文档 http://localhost:8000/docs）
- 前端页面：http://localhost:5173
- 默认管理员账号：`admin` / `admin123`

> 关闭 start.bat 这个窗口**不会**停止服务，需手动关掉后端 / 前端两个子窗口。

## 七、开发完提交并推送

```bash
git add .
git commit -m "feat: 你的改动说明"
git push origin main
```

新电脑首次 push 需先配置 Git 身份：

```bash
git config --global user.name "qq94028715"
git config --global user.email "qq94028715@users.noreply.github.com"
```

首次 push 会弹 GitHub 登录，**密码处填 Personal Access Token（PAT）**，不是 GitHub 账号密码。

## 八、三个关键坑

1. **两台电脑数据会分叉**：SQLite 是单文件，两边各自训练会产生不同数据。
   建议定一台「主开发机」跑数据，另一台只 `clone` 代码；需要同步时手动拷 `kefuxitong.db` 覆盖（**先停服务再拷**）。
2. **push 需要凭据**：见第七节的 PAT 说明。
3. **依赖装不上 / 太慢**：用国内镜像（见第三节 pip 镜像、第四节 npm 镜像）。

## 九、依赖版本锁定说明

为避免新电脑装到不兼容的新版依赖，仓库已做两层锁定：

- `backend/requirements.txt`：14 个直接依赖已钉为精确版本（`==`），保留用途注释，正常 `pip install -r requirements.txt` 即可。
- `backend/requirements.lock.txt`：完整冻结清单（含所有传递依赖），用于完全可复现安装。需要 100% 一致时可用 `pip install -r requirements.lock.txt`。
